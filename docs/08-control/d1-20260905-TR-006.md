## Orden de trabajo

### A — Este repo (primero; desbloquea lab)

1. **Constante operación** — `PaqContracts` (ej. `JobOperations.DiagnosticsRun`) o string fijo documentado `"diagnostics.run"`.
2. **`DiagnosticsRunner` (o método privado)** — Input: options SQL + identidad; Output: `(status, data, readiness)`. Ping: `SqlConnection.OpenAsync` + close; **no** queries libres. Sin config SQL → `degraded` / `sqlConnectionOk=false` (hub OK).
3. **`HandleExecuteJobAsync`** — Si `operation == diagnostics.run` → runner; else mantener stub seguro TR-005 (u `OPERATION_NOT_ALLOWED` para desconocidas — preferir: diagnostics real; otras = stub success mock **solo** si ya existía, no ampliar lista).
4. **Logs** — Al completar: `traceId`, `jobId`, `status`, `durationMs`, `readiness`, `sqlConnectionOk` (sin password).
5. **Tests** — Unit del runner con connection string inválida → degraded; con skip SQL / fake interface si hace falta.
6. **lab-local.md tramo 4** — Secuencia Gateway+Agente+curl `jobs/send` diagnostics; esperado success/degraded.
7. **Traza parcial** este repo.

### B — TANGO (en paralelo o justo después)

1. **`sendJob`** — Header `X-Paq-Internal-Api-Key`; body añade `traceId` (param opcional o `Str::ulid()` / UUID) y `timeoutSeconds`.
2. **`runDiagnostics(string $agentId, string $clientId, ?int $timeoutSeconds = null): array`** — `sendJob(..., 'diagnostics.run', [], $timeout)`; log duración + `traceId` (sin secretos).
3. **Config** — Documentar `AGENT_GATEWAY_URL` / `agent_gateway.url` lab vs VPC (`http://10.0.1.224:5100` ref). Key = misma que Gateway `Gateway__InternalApiKey`.
4. **PHPUnit** — Assert header y presencia de `traceId` en request fake (Http::fake), si hay harness.
5. **Sin fallback `host`** en este camino diagnostics (no abrir SQL directo si modo agente).
6. **Traza** TANGO (archivos/rama); no codear PHP en este repo.

### C — Verificación

1. Lab: agente online + diagnostics → `success` + `sqlConnectionOk` según SQL local.
2. Lab degraded: SQL malo/vacío + agente conectado → `degraded`.
3. Lab offline: agente parado → Gateway `offline` / `AGENT_OFFLINE`.
4. (Ops) AWS cuando haya agente Windows + keys Forge.

## Riesgos

| Riesgo | Mitigación |
|--------|------------|
| Romper callers TANGO que usan header viejo | Un solo header M1; coordinar deploy Gateway+Laravel |
| `traceId` faltante → 400 Gateway | Generar siempre en `sendJob` |
| SQL ping con credenciales malas en prod | Solo usa `appsettings.local` / config agente; logs sin password |
| Ampliar operations de más | Solo `diagnostics.run` en TR-006 |
| Confundir URL pública hub con internal | Laravel → `http://IP:5100`, nunca `gateway.paqsystems.com` para jobs |
