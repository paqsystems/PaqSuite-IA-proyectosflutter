## Orden de trabajo

### A — Este repo (primero; desbloquea lab del SP)

1. **`JobOperations.AuthLogin`** en `PaqContracts`.
2. **Localizar/embeber SP** — Buscar artefacto legado (`PAQ_Auth_Login` + `2026_06_29_000002_fix_col_rol_pk_fallback` si existe fuera de git). Dejar script(s) bajo path versionado + instrucciones lab (aplicar a mano en diccionario). Si no aparece el `.sql` en D: documentar dependencia “SP ya desplegado en lab” y mock en unit tests.
3. **`IAuthLoginExecutor` / `AuthLoginRunner`** — Input: connection string + `codigo`; Output: `JobResult` parcial (`status`, `data` Q3 o `failed` + `errorCode`). Ejecutar solo SP parametrizado (`@codigo` o nombre canónico del SP). Mapear multi-RS a:
   - `status: "OK"`
   - `user: { password_hash }`
   - `es_admin`, `redirectTo`, `empresas[]`
   - Si SP/negocio falla → `failed` + código (`NOT_FOUND`, `INACTIVE`, `SQL_ERROR`, …) alineado a lo que `throwGatewayBusinessError` espera.
4. **`HandleExecuteJobAsync`** — Branch `auth.login` → runner; `diagnostics.run` intacto; else `OPERATION_NOT_ALLOWED` (actualizar mensaje whitelist). Requiere readiness con SQL (`gateway_authenticated`+ no alcanza para login feliz → `degraded`/`AGENT_NOT_READY` si SQL no configurado).
5. **Logs** — `traceId`, `jobId`, `status`, `durationMs`; **nunca** password ni hash completo en info (hash truncado o omitido).
6. **Tests** — Operación inventada → `OPERATION_NOT_ALLOWED`; runner con executor fake success/failed.
7. **lab-local** — Secuencia: SP aplicado + SQL en `appsettings.local.json` + `jobs/send` auth.login con `codigo` de lab.
8. **Traza parcial** este repo.

### B — TANGO (corte duro login)

1. **`resolveAuthenticatedUser`** — Si `shouldUseGateway`:
   - `sendJob(agentId, clientId, 'auth.login', ['codigo' => $usuario], timeout, traceId)`.
   - `success` → `resolveAuthenticatedUserFromGatewayData` (sin cambio de contrato data).
   - `failed` → leer `errorCode`/`errorMessage` (y legacy `error.code` si aún aparece) → `throwGatewayBusinessError`.
   - `offline` / `timeout` / status desconocido / `AgentGatewayException` → **AuthException** `AGENT_OFFLINE` o `ERROR_AUTH_PROVIDER` (**sin** `validatePasswordViaSqlDirecto`).
2. **Tenants sin `agent_id`** — Siguen SQL directo (SPEC convivencia).
3. **PHPUnit** — Con `EmpresaConexion` mock/`shouldUseGateway` true: offline no toca DB users SQL directo; success con data OK + Hash; failed mapea código.
4. **Traza** TANGO (rama `FRAMEWORK`).

### C — Verificación

1. Lab REST: `auth.login` → `success` + data Q3 (con SQL+SP).
2. Lab REST: operation basura → `OPERATION_NOT_ALLOWED`.
3. Lab: agente parado → Gateway `offline`; Tinker/login API → sin SQL al cliente.
4. (Ops) AWS opcional.
