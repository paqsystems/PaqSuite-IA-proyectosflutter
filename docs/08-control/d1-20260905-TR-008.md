## Tipo de trabajo

Corrección / endurecimiento: HTTP 503 en login offline; auditoría de services Gateway; limpieza de logs engañosos; tests de regresión. **No** features nuevas. AuthService sin fallback **ya** está (TR-007).

## Alcance entendido

1. **`AuthController::login`:** mapear `AuthService::ERROR_AGENT_OFFLINE` → HTTP **503** (hoy cae en default 401). Respuesta JSON con señal clara `AGENT_OFFLINE` (mensaje y/o campo estable).
2. **Auditoría services** que usan `AgentGatewayClient` + `shouldUseGateway`: confirmar que offline/timeout/`AgentGatewayException` **no** abren SQL por `host`. Corregir solo si queda un camino real de fallback (grep preliminar: varios ya lanzan `HttpException(503)`; el problema frecuente es el **texto del log**).
3. **Logs:** renombrar mensajes tipo “fallback a SQL directo” → “Gateway degradado / AGENT_OFFLINE”; incluir `agent_id` / `cliente`; sin secretos.
4. **Legacy:** conservar SQL directo en AuthService **solo** cuando `!shouldUseGateway` (sin `agent_id`). No inventar dual-path en services gateway-only.
5. **Tests:** login HTTP o feature test → 503 + AGENT_OFFLINE; mantener/ampliar `AuthServiceGatewayModeTest`; test o assert de control (grep/fixture) contra reintroducción de fallback tras fallo Gateway.
6. **Fuera:** este repo (salvo docs Traza); UI; Tailscale; reabrir SQL en Pedidos/etc. sin `agent_id`; helper compartido obligatorio (opcional si reduce copia).

1. En todos los `catch (AuthException)` de login (y change-password si aplica el mismo match): añadir `AuthService::ERROR_AGENT_OFFLINE => 503`.
