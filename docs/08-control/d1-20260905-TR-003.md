## Orden de trabajo (paso D)

1. **Publish local documentado** — comando canónico:
   `dotnet publish src/PaqGateway -c Release -o artifacts/paqgateway`  
   (en EC2 destino: `/opt/paqgateway`). Verificar que el publish Release arranca con env de prod (sin `UseDevAuthStub`).
2. **Plantilla systemd** — `paqgateway.service`: User no-root, `WorkingDirectory=/opt/paqgateway`, `ExecStart=.../PaqGateway`, `Restart=always`, `EnvironmentFile=/etc/paqgateway/env` (o Environment=).
3. **Plantilla Nginx** — `server` 443 → `proxy_pass http://127.0.0.1:5100` solo para `/agent-hub` (y negotiate SignalR); headers Upgrade/Connection; **no** exponer `/internal/*` en el vhost público.
4. **Env producción** — documentar variables obligatorias (N5/N6): `Gateway__InternalApiKey`, `LaravelApi__BaseUrl`, `LaravelApi__InternalApiKey`, `ASPNETCORE_URLS=http://127.0.0.1:5100`, `ASPNETCORE_ENVIRONMENT=Production`.
5. **Actualizar runbook** — §10 → pasos numerados reales; SG (443 público, 5100 solo VPC, sin 1433); DNS/cert; cómo copiar artefactos (scp/SSM).
6. **Checklist verificación** — dejar §8 accionable; en Traza marcar qué pudo hacer el humano vs pendiente H12.
7. **Traza TR-003** — archivos, comandos, pendientes (VPC/DNS/auth Laravel si faltan). Estado → Pendiente de Revisión.

**Fuera de D automático:** crear EC2, abrir consolas AWS, emitir cert real, apuntar DNS (humano). Si el humano aporta datos de ficha §9 en el chat durante D, incorporarlos al runbook.

## Riesgos

| Riesgo | Mitigación |
|--------|------------|
| H12 VPC/DNS ausentes | D entrega runbook completo; Traza/Pendientes; no fingir e2e |
| `/internal/*` filtrado por Nginx público | Solo proxy `/agent-hub`; SG bloquea 5100 desde Internet |
| Stub Dev en prod | N5 + `ASPNETCORE_ENVIRONMENT=Production` |
| Auth Laravel aún no existe | Prueba WSS puede fallar en handshake auth; documentar; hub TLS+proceso up igual verificables |
